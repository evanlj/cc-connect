# 2026-03-23 飞书快捷打开 Squad 卡片与卡片文案精简说明

## 背景

现有流程里，用户需要先发送“菜单”打开菜单卡片，再点击“Squad 审核控制卡”按钮，才能进入 Squad 控制卡。  
为降低操作层级，新增“文本快捷触发 Squad 卡片”的能力；同时对菜单卡片与 Squad 卡片文案做精简，去掉冗长说明。

## 变更摘要

### 1) 新增快捷触发（文本直开 Squad 卡片）

在飞书 `text` 消息处理分支中新增识别逻辑：当收到以下文本时，直接弹出 Squad 控制卡：

- `/squad-card`
- `/squad_card`
- `squad卡片`
- `squad控制卡`
- `squad 控制卡`
- `squad 审核控制卡`

实现方式：

- `shouldShowSquadControlCard(text)`：判断是否命中快捷触发词
- `replySquadControlCard(ctx, rc, sessionKey)`：统一打开 Squad 卡片（优先 reply，失败后 fallback 到 send）

### 2) 菜单卡片文案精简

`buildMenuCardJSON()` 中精简了以下文案：

- 将顶部说明改为简短“请选择操作：”
- 将“多Bot讨论快捷操作”简化为“多Bot讨论”
- 底部说明改为短口令提示：`菜单`、`/squad-card`

### 3) Squad 控制卡文案精简

`buildSquadControlCardJSON()` 中：

- 顶部长段落介绍精简为：`填写 Run ID 后点击按钮执行；返工请填写说明。`
- 模板区提示精简为：`模板命令（可选）`

### 4) Squad 审核控制卡按钮排版调整（2026-03-23）

按最新交互要求，按钮文案与行布局调整为：

1. 文案调整
   - `运行列表` → `信息`
   - `查看任务` → `任务`
   - `查看计划` → `计划`
   - `裁决通过` → `任务通过`
   - `裁决返工` → `任务重做`

2. 行布局调整
   - 第一行：`信息`、`状态`
   - 第二行：`计划`、`批准计划`
   - 第三行：`任务`、`批准任务`、`跳过任务`
   - 第四行：`任务通过`、`任务重做`

3. 返工输入区调整
   - 将输入区标题从 `返工或跳过说明` 调整为 `返工原因`
   - 将该输入框下移到第四行按钮（`任务通过`、`任务重做`）之后，便于紧邻裁决操作填写
   - 占位提示调整为：`不通过原因与修改方案`

4. 提示信息进一步精简
   - 去除卡片顶部提示行：`填写 Run ID 后点击按钮执行；返工请填写说明。`
   - 去除 `Run ID` 输入框标签提示（保留占位符）
   - 去除 `返工原因` 输入框标签提示（保留占位符）

5. 审核控制卡新一轮排版与按钮规范（2026-03-23）
   - 按钮文案：
     - `信息` 调整为 `统计`
     - `批准计划` 调整为 `批准`
   - 按钮布局：
     - 第一行：`统计`、`状态`、`计划`、`批准`
     - 第二行：`任务`、`批准任务`、`跳过任务`
     - 第三行：`任务通过`、`任务重做`
   - 按钮风格：全部使用默认样式（不再使用 primary/danger 颜色强调）
   - Run ID 输入框：
     - 去除 `max_length` 字数计数提示
     - 保持输入文本默认左对齐显示

6. 去除模板按钮并改为单行 tips（2026-03-23）
   - 删除 `模板命令（可选）` 标题行
   - 删除模板按钮区（启动模板 / 计划确认 / 任务确认 / 跳过模板 / 返工模板）
   - 新增单行提示：
     - `/squad start --repo G:/AgeAction/AgeActionExample --planner-timeout-sec 3600 实现一个新的Action结点，当前项目没有的功能`

## 验证建议

1. 飞书发送 `/squad-card`，应直接打开 Squad 控制卡；
2. 飞书发送 `菜单`，仍能打开菜单卡片；
3. 在菜单卡片中点击“Squad 审核控制卡”，应正常打开 Squad 控制卡；
4. 卡片按钮命令行为保持不变（`/squad status`、`/squad approve-plan` 等）。

## 影响与风险

- 正向：减少一次点击路径，提升操作效率；
- 风险：若触发词设得过宽可能误触发；本次采用精确匹配以降低误触发概率。
