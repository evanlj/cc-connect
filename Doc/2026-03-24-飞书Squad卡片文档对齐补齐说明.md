# 2026-03-24 飞书Squad卡片文档对齐补齐说明

## 背景

对照文档《2026-03-23-飞书快捷打开Squad卡片与卡片文案精简说明》与当前代码实现后，发现存在“功能已实现但文案/布局未对齐”的偏差，主要集中在菜单卡片与 Squad 控制卡的排版和文案版本不一致。

## 差异清单（补齐前）

1. 菜单卡片文案仍为旧版本
   - 顶部仍包含较长说明文案
   - “多Bot讨论快捷操作”未改为“多Bot讨论”
   - 底部仍为“也可以直接发一句话描述需求...”，不是“菜单 / /squad-card”短口令提示

2. Squad 控制卡仍为旧布局
   - 按钮文案仍为“运行列表 / 查看计划 / 查看任务 / 裁决通过 / 裁决返工”等旧词
   - 按钮行布局与文档要求不一致
   - 输入区仍是“返工或跳过说明”
   - 仍包含 `max_length` 提示
   - 仍包含模板区（启动模板、计划确认、任务确认、跳过模板、返工模板）
   - 缺少单行 `/squad start ...` 提示语

3. 开卡逻辑复用未统一
   - 文本触发与菜单按钮触发的 Squad 开卡路径未完全复用同一函数

## 实现方案与落地

### 1) 统一 Squad 开卡函数

文件：`platform/feishu/feishu.go`

- 新增并统一使用 `replySquadControlCard(ctx, rc, sessionKey)`：
  - 文本触发 `/squad-card` 走同一函数
  - 菜单按钮 `squad_control_card` 走同一函数
  - 统一策略：优先 `reply`，失败再 `send`

### 2) 菜单卡片文案对齐

文件：`platform/feishu/feishu.go` -> `buildMenuCardJSON()`

- 顶部改为：`请选择操作：`
- 分组标题改为：`多Bot讨论`
- 底部改为：`快捷口令：菜单、/squad-card`

### 3) Squad 控制卡布局与文案对齐

文件：`platform/feishu/feishu.go` -> `buildSquadControlCardJSON()`

- 按钮行调整为：
  - 第一行：`统计`、`状态`、`计划`、`批准`
  - 第二行：`任务`、`批准任务`、`跳过任务`
  - 第三行：`任务通过`、`任务重做`
- 按钮统一为默认样式（`default`）
- `Run ID` 与 `返工原因`输入框去除标签提示，只保留占位符
- 移除 `max_length` 字数限制展示
- `返工原因`输入框下移到第三行按钮后
- 删除模板区与模板按钮
- 新增单行提示：
  - `/squad start --repo G:/AgeAction/AgeActionExample --planner-timeout-sec 3600 实现一个新的Action结点，当前项目没有的功能`

## 影响与风险

### 正向影响

- 文档与功能实现重新一致，减少“文档说一套，界面是另一套”的沟通成本
- 开卡逻辑统一后，维护成本下降

### 风险

- 卡片文案变更后，用户可能需要短暂适应新按钮命名
- 若飞书端事件权限不足，仍可能出现“打开卡片失败”提示（与本次文案对齐无关）

- `buildSquadControlCardJSON()` 的旧布局与模板区

回滚后执行 `go test ./platform/feishu` 验证。
