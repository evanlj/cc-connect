# 2026-03-23 `cc-connect ask` 结构化输出与轨迹时间线实现说明

## 1. 背景

现有 `cc-connect ask` 命令仅输出人类可读文本，虽然 `content`、`latency_ms`、`tool_count` 在 API 层可拿到，但缺少：

1. CLI 级别可直接供前端消费的结构化 JSON；
2. 可展示“思考 / 工具 / 文本”过程的事件时间线（timeline）。

这导致前端或自动化调用方需要自行拼接结果，且无法稳定回放执行过程。

## 2. 变更摘要

### 2.1 `AskSession` 增加轨迹采集

- 文件：`core/engine_ask.go`
- 新增类型：`AskTimelineEvent`
  - `type`：事件类型（`thinking` / `tool` / `text`）
  - `at_ms`：相对本次 ask 开始时间的毫秒偏移
  - `content` / `tool_name` / `tool_input`：事件展示数据
- `AskResult` 新增 `timeline` 字段。
- 在 `AskSession` 事件循环内按到达顺序写入 timeline：
  - `EventThinking` → `thinking`
  - `EventToolUse` → `tool`
  - `EventText` / 最终结果补齐 → `text`

### 2.2 `/ask` API 返回 timeline

- 文件：`core/api.go`
- `/ask` 成功响应新增 `timeline` 字段，直接透传 `AskSession` 采集结果。

### 2.3 本地实例客户端解码 timeline

- 文件：`core/instance_client.go`
- `LocalInstanceClient.Ask` 解析响应时新增 `timeline` 解码并回填到 `AskResult`。

### 2.4 `cc-connect ask` 新增 `--json`

- 文件：`cmd/cc-connect/ask.go`
- 新增参数：`--json`。
- 重构执行路径为 `runAskWithIO`，保留原文本输出行为；
  - 默认（无 `--json`）仍输出：
    - `Session: ...`
    - `Latency: ...`
    - `Tools: ...`（有工具才显示）
    - 分隔线和正文
  - `--json` 时输出合法 JSON（含 `status`、`session_key`、`content`、`latency_ms`、`tool_count`、`timeline`）。

## 3. 影响面与风险

### 影响面

1. `AskSession` 结果结构扩展（新增 `timeline`）；
2. `/ask` API 响应新增字段；
3. CLI `ask` 子命令新增 `--json` 输出模式。

### 风险评估

- **兼容性风险低**：JSON 为向后兼容新增字段，默认文本输出不变。
- **体积风险可控**：timeline 仅记录 `thinking/tool/text`，且按事件流自然增长，不引入额外外部依赖。
- **解析风险可控**：CLI 在 `--json` 模式下先解码再重新编码，确保输出 JSON 合法。
