# 2026-03-22 Squad A规则审核权限收敛实现说明

## 1. 背景

在多轮 Squad 执行中，流程经常停留在 `reviewing_task` 阶段较长时间。  
根因之一是 Reviewer 审核范围过宽，容易把环境噪音（如 Licensing、Android SDK、UnityConnect）误当作任务阻塞项，导致：

1. 审核耗时显著增加；
2. 返工理由与当前任务计划不一致；
3. 用户体感为“卡在审核者”。

为解决该问题，本次按 **A规则** 收敛 Reviewer 审核权限：只审核“代码实现与文档是否符合计划”。

---

## 2. 变更摘要

### 2.1 Reviewer Prompt 增加 A规则硬门禁

文件：`core/squad_runner.go`  
函数：`buildSquadReviewerPrompt`

改动要点：

1. Reviewer Prompt 新增“审核权限硬门禁（A规则）”：
   - 仅审核代码实现 + Doc 文档与计划一致性；
   - 仅允许基于执行者声明变更文件进行审查；
   - 禁止把环境噪音计入 `failed_reasons`；
   - `failed_reasons` 必须使用锚点格式：`[ACC:验收点] [FILE:文件路径] 问题描述`。
2. Prompt 显式注入执行者声明的 `changed_files` 与 `test_result`，减少 Reviewer 无边界扩展扫描。

### 2.2 新增审核结果范围过滤（防越界）

文件：`core/squad_runner.go`  
新增函数：

- `filterReviewerFindingsByScope`
- `containsSquadReviewNoise`
- `hasSquadReviewAnchor`
- `extractSquadReviewAnchorValue`
- `normalizeSquadFileKey`
- `isSquadFileInScope`
- `reviewResultImpliesBlocking`

过滤规则：

1. 过滤环境噪音类原因（关键词白名单）；
2. 过滤无锚点 `failed_reasons`；
3. 过滤文件不在 `changed_files` 范围内的原因；
4. 全部原因被过滤后，自动降级为“未发现可阻塞计划偏差（由用户裁决）”。

### 2.3 审核事件增加可观测字段

文件：`core/squad_runner.go`  
事件：`task reviewed`

新增字段：

- `review_scope=plan_code_doc_only`
- `filtered_reasons`
- `noise_reasons`
- `out_of_scope_reasons`
- `unanchored_reasons`

并在通知文案中补充“reviewer_filter”统计，帮助快速识别越界审核被拦截的情况。

---

## 3. 影响与风险

### 3.1 正向影响

1. Reviewer 审核范围更聚焦，降低“卡在审核者”的概率；
2. `failed_reasons` 可追溯到验收点与文件，便于用户裁决；
3. 环境噪音不再轻易触发无意义返工。

### 3.2 风险与取舍

1. 若 Reviewer 未按格式输出锚点，`failed_reasons` 可能被过滤为 0；
2. 在极端情况下，可能出现“真实问题但表述不规范被过滤”的漏报风险；
3. 该风险通过用户最终裁决机制（`/squad judge-review`）兜底。

## 4. 验证证据

### 4.1 新增测试

文件：`core/squad_review_scope_test.go`

覆盖点：

1. `TestBuildSquadReviewerPrompt_ContainsScopeGuards`
   - 验证 Prompt 已包含 A规则硬门禁文本、锚点格式要求、变更文件与测试结果注入。
2. `TestFilterReviewerFindingsByScope_DropsNoiseAndOutOfScope`
   - 验证噪音原因 / 无锚点原因 / 越界文件原因被过滤，仅保留计划内有效问题。
3. `TestFilterReviewerFindingsByScope_AllDroppedFallbackToNonBlocking`
   - 验证全部被过滤时自动降级为非阻塞结论。
