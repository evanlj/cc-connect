# 2026-03-22 任务产出 Markdown 自动发送飞书说明

## 1. 背景

用户希望在任务流程中，凡是系统自动生成的 `.md` 文档（例如计划、最终报告）都能自动回传到飞书，而不是只发送本地路径。

## 2. 本次实现范围

在现有 `send-file` 能力基础上，新增了“生成即自动发送”的流程挂钩：

1. **Squad 计划文档**（`plan.md`）生成后自动发送；
2. **Squad 最终报告**（`final-report.md`）生成后自动发送；
3. **Debate 最终报告**（`*-final.md`）生成后自动发送。

## 3. 实现原理

### 3.1 核心方法

在 `core/engine_ask.go` 增加内部方法：

- `autoSendMarkdownArtifact(sessionKey, filePath string) error`

行为：

- 仅处理 `.md` 文件；
- 调用 `SendFileBySessionKey` 上传并发送附件；
- 平台不支持文件发送时（`ErrNotSupported`）自动跳过，不中断主流程；
- 真实失败（路径不存在、上传失败、权限不足）返回错误，由调用方提示用户。

### 3.2 流程挂点

- `core/squad_runner.go`
  - `runSquadPlanning`：`plan.md` 保存后自动发送；
  - `runSquadExecutionLoop` 完成阶段：`final-report.md` 保存后自动发送。
- `core/debate_runner.go`
  - 共识流程结束保存最终报告后自动发送。

## 4. 用户侧效果

当你运行 `/squad` 或 `/debate`，并生成最终 Markdown 产物时，飞书会话将出现：

1. 原有文本通知（run_id、路径、状态）；
2. 自动发送的文件附件（`.md`）。

如果自动发送失败，会追加一条错误说明（不影响任务主流程继续完成）。

## 5. 影响与风险

### 正向影响

- 减少手工二次发送；
- 群内可直接查看/下载产出文档；
- 任务闭环更完整。

### 风险点

- 飞书侧权限或文件大小限制可能导致上传失败；
- 非飞书或不支持文件发送的平台会自动跳过（不会报错中断）。

## 6. 验证建议

1. 触发一轮 `/squad start ...`，在计划生成后检查是否收到 `plan.md`；
2. 完成全部任务后检查是否收到 `final-report.md`；
3. 触发一轮 `/debate ...` 到结束，检查是否收到 `*-final.md`。

若未收到附件，查看实例日志中 `auto send` 相关失败信息。
