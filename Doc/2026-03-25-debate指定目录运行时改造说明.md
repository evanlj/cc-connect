# 2026-03-25 debate指定目录运行时改造说明

## 背景

现有 `debate` 模式默认使用固定实例（`instance-mutilbot1~5`）的固定 `project/work_dir`，无法在一次讨论中把所有角色统一定位到用户指定的项目目录（例如 `D:/test`）。  
这会导致“讨论需求与目标项目上下文不一致”，降低讨论结果可执行性。

## 变更摘要

本次改造在 `debate` 模式新增“按房间动态运行时”能力：

1. `debate start` 新增参数：
   - `--repo` / `--repo-path`：指定本轮讨论项目目录（绝对路径）
   - `--provider`：指定运行时 provider（可选）
2. 新增 `DebateProcessManager`：
   - 按 room 动态拉起角色进程（本地 `api.sock`）
   - 运行时 `work_dir` 统一绑定到 `--repo`
   - 运行时进程不连接飞书（复用 squad 运行时平台裁剪逻辑）
3. `DebateRoom` 新增运行时元信息：
   - `repo_path`、`provider`
   - `runtime_enabled`、`runtime_root`
   - `role_runtime`（每角色 project/socket/pid）
4. `/debate status` 增强：
   - 展示 repo/provider/runtime 状态
   - 展示每个角色 socket 就绪状态
5. `/debate stop` 增强：
   - 停止讨论时同步回收 room 对应运行时进程

## 影响与风险

### 影响

- 用户可直接使用以下命令发起“指定目录上下文”的多人讨论：

```text
/debate start --mode consensus --repo D:/your-repo --provider codez <问题>
```

- 房间级隔离更清晰：每个 room 使用独立 runtime root 与 project 名称。

### 风险

1. **运行时路径过长**（Windows `AF_UNIX` 常见问题）  
   - 已沿用短根目录策略（`CC_DEBATE_RUNTIME_ROOT` + 默认短目录）与 socket 长度检查。
2. **运行时进程未正常回收**  
   - 在 `/debate stop` 与 `Engine.Stop()` 中增加统一回收。
3. **模板角色识别失败**  
   - 运行时角色模板复用 `resolveRoleTemplateConfig`，若角色不在模板映射内会显式报错。

## 验证证据

建议执行以下验证：

1. **参数解析与校验**
   - `go test ./core -run TestParseDebateStartOptions -v`
2. **运行时根目录与状态格式**
   - `go test ./core -run "TestResolveDebateRuntimeRoot|TestFormatDebateRuntimeRolesStatus" -v`
3. **手工联调**
   - 发送：
     - `/debate start --mode consensus --repo D:/test --provider codez 讨论xxx`
     - `/debate status <room_id>`
   - 预期：
     - `repo_path` 显示 `D:/test`
     - `runtime_enabled=true`
     - `runtime_roles` 中每个角色有 `socket_state=ready`

## 回滚说明

如需快速回滚本改造：

1. 回退本次提交（或使用上一稳定 commit）。
2. 恢复 `debate` 仅使用固定实例映射的旧行为。
3. 运行时目录可手动清理（如 `CC_DEBATE_RUNTIME_ROOT` 指向目录）。
